# 仕様書を霊夢と魔理沙の掛け合いにする Agent Skill を作ってみた

![ゆっくり解説スライドのスクショ](https://static.zenn.studio/user-upload/382443286dea-20260809.png)
:::message
記事・リポジトリ掲載のイラストは自作です（東方Project二次創作ガイドライン準拠）
:::

```sh
/yukkuri-slides {ドキュメントやURL}
```

これだけで、仕様書が霊夢と魔理沙の掛け合いスライドになります。

## 使い方

スキル本体は https://github.com/paterapatera/yukkuri-slides にあります。

1. リポジトリの `.agents/skills/yukkuri-slides/` を、自分のプロジェクトの `.agents/skills/` 配下に置く
2. 必要なら `assets/` 内の 4 ファイル（`れいむ.png` / `まりさ.png` / `OPED.png` / `本編背景.png`）を差し替える（ファイル名はそのまま）
3. チャットで `/yukkuri-slides` に続けて、解説したい Markdown・仕様書・URL を渡す
4. 生成された `yukkuri-slides.html` をブラウザで開く（`→` / `Space` / クリックで進む）

動作確認しているのは Cursor のみです。

中身は Agent Skills 形式の Markdown と HTML テンプレートなので、同じ仕組みで動く他ツールでも動くと思いますが、未検証です。

## なぜ作ったか

最近、仕事で仕様駆動開発（SDD）を社内に広める活動をしているのですが、AIの書く仕様書が本当に読みづらくて辛いです。

とにかく目が滑ります。最後まで読んだのに、何も記憶に残らない。

なぜ読みづらいのか、なぜ頭に入ってこないのか考えました。

そんなとき、いつものように YouTube で IT 関係のゆっくり解説を見ていて、「あぁ、ゆっくりに解説してもらえれば一生読んでられるじゃん」と思ったわけです。

気をつけてほしいのは、これは仕様書の**置き換え**ではない、ということです。

次のような使い方を想定しています。

- 長い仕様を読む前の「ざっくり把握」（用語・手順・結論の骨組み）
- レビュー前に「何が論点か」を掛け合いで聞き直す
- 用語定義・手順・Before/After・制約の箇条書きなど、口で説明しやすい部分

短い〜中くらいの仕様・設計メモ・手順書のように、結論と理由が文章になっているものが向いています。

向いていないのは、条文どおりの一字一句確認や、表が巨大な付録そのものです。

そこは原文を見ましょう。

ゆっくりスライドは「頭に入れるための補助」だと思ってください。

## 作り方

このスキルは AI に作ってもらいました。

どういうやり取りをしたのか、書いていきます。

仕組み自体は単純です。

大事なのは、ゆっくり解説として崩れないように**制約をスキルに埋め込む**ところだと思います。

完成したスキルの中身はだいたいこうです。

```
.agents/skills/yukkuri-slides/
├── SKILL.md          # 構成・口調・レイアウトの規約
├── template.html     # 16:9 の骨格・CSS・キーボード操作
├── patterns.md       # 本題の見せ方（比較・差分・ターミナル等）
└── assets/           # キャラ2種＋背景2種
```

### 1. 素材を用意する

霊夢・魔理沙の立ち絵と、茶番用／本編用の背景を用意します（ファイル名はスキル側の指定どおり）。

今回の記事・リポジトリに載せているイラストは自作です。

### 2. AI にスキルを依頼する

Cursor で用意されている `/create-skill` スキルを使いました。

だいたい次のような内容です。

```
/create-skill 指定されたドキュメントを読んで、「ゆっくり動画解説」風のスライドHTMLを作成するスキルを作りたい。
スライドのアスペクト比は16:9になるようにしてください。

必須の要素：
- 霊夢、魔理沙の掛け合い
- 本題に入る前の茶番
- 本題に入る前に「ゆっくりしていってね！！！」というスライド
- ゆっくり魔理沙／霊夢の口調
- シンプルな背景＋大きめの見出し／本文
- キャラ立ち絵や吹き出し

入力は「指定されたドキュメント」（Markdown / URL など）を読む想定

スキル名：yukkuri-slides

素材： {用意した素材を貼り付ける}
```

ここで大事にしたのは「きれいな HTML を書いて」ではなく、**順番と禁止事項**を決めることです。

茶番なしで本題に入らない、「ゆっくりしていってね！！！」を省略・言い換えしない、16:9を崩さない、といった制約を最初から書くようにしました。

### 3. 出来上がったスキルを試す

今回は、手元にあったスキル修正指示書の要約資料を入力にして、ゆっくり解説スライドを生成してみました。

![茶番スライドのスクショ](https://static.zenn.studio/user-upload/2895d57bcb18-20260809.png)
*本題の前に無駄話が入る。ここがないと「解説スライド」になってしまう。*

![比較スライドのスクショ](https://static.zenn.studio/user-upload/9b8ad33d01c2-20260809.png)
*`patterns.md` の比較型。仕様の Before/After や選択肢の対比向き。*

最初に茶番があり、本題では比較表示もきちんと出て、骨組みとしては問題なさそうでした。

ここから先は「動く」を「見られる」にする作業です。

### 4. スキルの微調整

AI を使ううえで、個人的に一番大変だと思っているのはデザインまわりです。

たとえばフォントの大きさや配置、色などは、人間の目で判断して細かく決めたほうが綺麗にできると思っています。

AI任せだとこんな感じで見づらい部分があったりする。
![見づらいフォントのスクショ](https://static.zenn.studio/user-upload/6608b80ed668-20260809.png)


今回、微調整や修正指示したのは次のとおりです。

- 魔理沙と霊夢の字幕フチを `#000` に統一（背景の上でも読みやすくするため）
- `vw` やざっくりした可変指定をやめ、1920×1080 基準でスケールする方式に変更（リサイズで文字比率が崩れないように）
- 1920×1080より小さいウィンドウで中央からズレる問題を修正
- 立ち絵の位置を下端から少し上げる（`bottom: 1%`）。足元が切れて見えにくかったため

AI は一発で「いい感じ」のものを出してくれますが、字幕が読めるか・小さい画面で破綻しないかは、人間が見て直した方が早いです。

その結果を `template.html` と `SKILL.md` に戻しておくと、次から同じ失敗を繰り返しにくくなります。

## おわりに

やっていることの骨格は単純です。

ドキュメントを読んで、決まった構成の HTML を1ファイル出す。
ただし、「ゆっくり」にするために、茶番・定番フレーズ・口調・見せ方パターンといった**崩すと一気にただの資料になる制約**をスキル側に書いておくのがコツです。

いままでスキルに触れたことのなかった人が、これをきっかけにスキルを使ってみるようになったら嬉しいです。

その延長で、「自分でも書いてみよう」と思う人が増えたら、なお嬉しいです。

重い仕組みがなくても、制約を書いたスキルなら同じノリで作れます。

気になった人は、まず手元の仕様書や README を1本投げてみてください。

スキル本体はこちらです。  
https://github.com/paterapatera/yukkuri-slides

茶番から入って「ゆっくりしていってね！！！」が出たら成功です。

物足りない部分があれば、ぜひ自分好みにスキルをカスタマイズしてみてください。
